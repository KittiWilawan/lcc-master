# ฝึกโมเดลสำหรับกล้อง Android

## ขั้นตอน

1. สำรอง assets และรายงานเดิมก่อนเริ่ม
2. ใช้ `extract_runtime_sequences.py <extraction-config.json>` ดึงท่าทางตามเวลา ด้วย MediaPipe task ที่จะใส่ใน APK ขนาดภาพและความถี่มาจาก runtime configuration
3. ใช้ `train_runtime_classifier.py <training-config.json>` ฝึกโมเดลและเลือกจาก validation เท่านั้น
4. ใช้ `export_android_pose_model.py` ส่งออกโมเดล โดยส่ง `--metadata-template` ให้ตรงกับการ normalize ตอนฝึก
5. ตรวจ parity และทดสอบคลิปผ่าน decoder, AI และ foreground service ใน release emulator ก่อนเปลี่ยน APK ที่แจก

เส้นทางไลบรารี ชุดข้อมูล จำนวน worker การเพิ่มตัวอย่าง พารามิเตอร์โมเดล น้ำหนักแหล่งข้อมูล และ threshold เป็น configuration ของแต่ละรอบ เก็บ configuration และผลดิบไว้พร้อมโมเดลเพื่อทำซ้ำได้

## การแบ่งข้อมูล

- แยกผู้เข้าร่วมระหว่าง train / validation / test และตรวจ SHA256 ของวิดีโอไม่ให้ซ้ำข้ามชุด
- ท่าทางต่อเนื่องทั้งหมดจากคลิปหนึ่งอยู่ในชุดเดียวกัน ห้ามสุ่มแยก window ของคลิปเดียวไป train และ test
- ตัวอย่างที่เสริมจาก cache ใช้เฉพาะ train และต้องรายงานวิธีสร้าง keypoints และการแบ่งกลุ่มของแหล่งนั้น
- คลิปที่เคยใช้ค้นหาข้อผิดพลาดต้องเรียกชุด regression ไม่ใช่การทดสอบแบบไม่เคยเห็น
- การดูคะแนน test แล้วปรับพารามิเตอร์ซ้ำทำให้ชุดนั้นเป็นข้อมูลพัฒนา ต้องบอกในรายงาน
- ใช้ `select_runtime_profile.py <model-selection.json> <training-configs...>` เลือกโปรไฟล์จากผล validation ของ cohort เดียวกัน เก็บ SHA256 ของโมเดลที่เลือก ก่อนวิเคราะห์ held test
- ใช้ `diagnose_runtime_classifier.py <model-selection.json> <output.json>` หลังแช่แข็งโมเดล เพื่อบันทึกการพลาด/แจ้งผิดรายคลิป เครื่องมือนี้ไม่ fit โมเดลและไม่เปลี่ยน threshold

## ข้อจำกัดของป้ายกำกับ

ข้อมูลปัจจุบันส่วนหนึ่งมีป้ายกำกับระดับคลิป ไม่มีเวลาที่เริ่มล้ม การใช้ window ช่วงท้ายของคลิปล้มเป็นตัวอย่างบวกเป็น weak supervision ต้องรายงานสัดส่วนที่ใช้ และห้ามอ้างว่ามี annotation เวลาเริ่มล้มจริง

คลิปปกติใช้หลายช่วงเวลาเพื่อให้ครอบคลุมการนั่ง ก้ม นอน และลุก หน้าต่างหลังเฟรมหายใช้เฉพาะท่าทางที่เห็นจริง และยังต้องมีผลบวกยืนยันซ้ำ การไม่เห็นคนไม่ใช่หลักฐานการล้ม

การดึงข้อมูลที่พบหลาย pose จะเว้นเฟรมนั้นไว้เพื่อไม่ยกป้ายกำกับของผู้เข้าร่วมไปให้คนอื่นโดยอัตโนมัติ ต้องตรวจห้องหลายคนแยกผ่าน pipeline จริง การติดตามกรอบไม่ใช่การยืนยันชื่อบุคคล

## การวัด

รายงานทั้งจำนวนคลิป ความไวในการจับการล้ม การแจ้งผิด และคลิปที่ไม่พบท่าทางเพียงพอ อย่ารายงาน accuracy อย่างเดียว ผล offline จาก pose ที่ดึงไว้กับผล Android live stream เป็นคนละการทดสอบ

เวลาตั้งแต่เริ่มเปิดคลิปจนแจ้งเตือน ไม่ใช่เวลานับจากเริ่มล้ม หากยังไม่มีป้ายกำกับเวลาเริ่มล้ม การวัดจาก emulator ไม่รับรองการใช้งานบนมือถือจริงหรือทุกสภาพแสง

## รอบวันที่ 7 ตุลาคม 2026

- ฝึก 9 candidates ใน 4 โปรไฟล์ ผู้ชนะใช้ 3 เฟรม, minTrackFrames=2, confirmations=2 และ threshold 0.45; เริ่มแจ้งได้เมื่อมีภาพจริงอย่างน้อย 3 ภาพ
- 1,268 คลิป train / 407 validation / 499 test จากสองชุดข้อมูล แยกผู้เข้าร่วมและ SHA ทั้งหมด ผู้ชนะใช้ 11,875 windows โดยไม่ใช้ supplemental FallVision
- Offline 499 คลิป: 92.6%, พลาด 18, แจ้งผิด 19; GMDCSA24 แยกได้ 78.4% จึงยังไม่ผ่านเป้าหมายทั่วไป 95%
- Native release HLS 52 คลิป: 88.5%, พลาด 4 จาก 26 คลิปล้ม, แจ้งผิด 2 จาก 26 normal; APK เดิมบนคลิปเดียวกันได้ 76.9%
- ตัวหาจุดข้อต่อ MediaPipe Lite ไม่ได้ฝึกใหม่ การฝึกเป็นตัวจำแนกการล้ม ส่วนการหายของ pose และ track เปลี่ยนยังเป็นข้อจำกัด
- รายงานและภาพจริงอยู่ `AI_IMPROVEMENT_REPORT_TH.md` และ `test-artifacts/ai-improvement-2026-10-07/REPORT_TH.html`

## การฝึกเพิ่มเติมด้วยมุมภาพและตัวอย่างยาก

ใช้ `train_runtime_refinement.py <config.json>` เพื่อสร้างหน้าต่างฝึกจากผู้เข้าร่วม train เท่านั้น การกลับซ้าย/ขวาสลับจุดข้อต่อและ visibility ตาม permutation ใน configuration การจำลองระยะกล้องและตำแหน่งใช้ transform เดียวตลอดหน้าต่าง รักษาทิศทางการเคลื่อนที่และ skeleton ที่ normalize แล้ว ตัวอย่างเหล่านี้เป็นข้อมูลสังเคราะห์จาก features ไม่ใช่คลิปใหม่หรือการเพิ่มสภาพแสงจริง

ก่อนเพิ่มน้ำหนักตัวอย่างยาก แบ่งผู้เข้าร่วม train เป็น folds ฝึกบนกลุ่มอื่นและให้คะแนนกลุ่มที่กันออก เก็บรายชื่อกลุ่มและ fingerprint ของ features, labels, groups และ mining configuration พร้อม cache คะแนน ห้ามใช้ความผิดพลาดจาก validation/test เพื่อให้น้ำหนักหน้าต่างฝึก น้ำหนักต่อคลิปหารด้วยจำนวนหน้าต่างเพื่อไม่ให้วิดีโอยาวมีน้ำหนักมากโดยอัตโนมัติ

รวมโมเดลใน APK ปัจจุบันในการเลือกด้วย `select_runtime_profile.py` แช่แข็งโมเดลและ SHA ก่อนใช้ `evaluate_runtime_refinement.py <evaluation-config.json>` เทียบชุด regression และ challenge แยก โมเดลทดลองที่คะแนนดีเฉพาะ validation แต่พลาดล้มเพิ่มหรือแจ้งผิดเพิ่มต้องไม่แทนโมเดลปัจจุบัน ผล offline ที่ผ่านยังต้องตรวจ Android HLS จริงก่อนเปลี่ยน APK

คลิปผู้สูงอายุที่มีเฉพาะ fall ใช้วัด recall ได้ แต่ใช้วัด specificity หรือรับรอง accuracy ทั้งการล้มและกิจวัตรไม่ได้ หากคลิปมีผู้ดูแลแต่ไม่มี annotation ว่าบุคคลใดล้ม การได้ผลบวกในคลิปไม่พิสูจน์ว่าระบุตัวผู้สูงอายุถูกต้อง ให้รายงานคลิปที่ไม่มีหน้าต่างหรือมีหลักฐานต่อเนื่องไม่พอยืนยันเหตุด้วย

รอบที่ 2 วันที่ 7 ตุลาคม: ฝึก 12 โมเดลใน 4 โปรไฟล์และ mining 3 folds จาก train เท่านั้น ผู้ชนะ validation 93.1% แต่ regression 499 คลิปได้ 92.4% เทียบโมเดล 1.0.6 ที่ 92.6% แจ้งผิดเพิ่ม 19 → 22 และ challenge ผู้สูงอายุพบเหตุลด 14/28 → 13/28 จึงไม่เปลี่ยน assets หรือ APK รายงานอยู่ `AI_RETRAINING_ROUND2_REPORT_TH.md` และ `test-artifacts/ai-retraining-2026-10-07-round2/REPORT_TH.html`

ตรวจรายงานพบสำเนาคลิปล้มซ้ำ 1 รายการภายใน regression ไม่มีสำเนาซ้ำใน train/validation และไม่มี SHA ซ้ำข้าม partition จำนวนทดสอบจึงเป็น 499 รายการ / 498 วิดีโอไม่ซ้ำ เมื่อนับ SHA แต่ละครั้งเดียว รุ่นปัจจุบัน 92.8% เทียบรุ่นทดลอง 92.6% ผลตัดสินคงรุ่นเดิมเหมือนเดิม บันทึกทั้งคะแนนดั้งเดิมและคะแนนวิดีโอไม่ซ้ำ ห้ามเปลี่ยน threshold ตามผลแก้การนับนี้
